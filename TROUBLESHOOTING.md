# Устранение проблемы после docker system prune

## Проблема
После выполнения `docker system prune -af` удаляются все Docker образы, включая `chrome-vnc-custom`, что приводит к ошибкам при запуске контейнеров.

## Решение

### 1. Сборка образа заранее (рекомендуется)

Запустите скрипт для предварительной сборки образа:

```bash
python3 build_image.py
```

Этот скрипт:
- Найдет правильный путь к `chrome_builder`
- Соберет образ `chrome-vnc-custom`
- Покажет подробные логи сборки
- Сообщит об успехе или ошибке

### 2. Проверка наличия образа

```bash
docker images | grep chrome-vnc-custom
```

### 3. Ручная сборка (если скрипт не работает)

```bash
cd chrome_builder
docker build -t chrome-vnc-custom .
```

## Проблемы и их решения

### Ошибка 137 (OOM Killer)
Если сборка падает с ошибкой 137, это означает нехватку памяти:

1. Увеличьте память для Docker (Docker Desktop -> Settings -> Resources)
2. Закройте другие приложения
3. Попробуйте сборку с `--no-cache`:
   ```bash
   docker build --no-cache -t chrome-vnc-custom chrome_builder/
   ```

### Неправильный путь к контексту сборки
Код теперь автоматически ищет папку `chrome_builder` в нескольких местах:
- `/app/chrome_builder` (в контейнере)
- `./chrome_builder` (относительный путь)
- Абсолютный путь от текущей директории
- Относительно файла `containers.py`

### Долгая сборка во время API запроса
Теперь рекомендуется собирать образ заранее, а не во время API запросов.

## Рекомендации

1. **Всегда собирайте образ заранее** перед запуском API
2. **Не удаляйте образы без необходимости** - используйте `docker system prune` без флага `-a`
3. **Мониторьте использование памяти** при сборке образов
4. **Проверяйте логи** при ошибках сборки для точной диагностики

## Проверка работоспособности

После сборки образа проверьте работу API:

```bash
curl -X POST "http://localhost:8080/create" \
  -H "Content-Type: application/json" \
  -d '{"user_id": "test", "website": "scopus"}'
```
